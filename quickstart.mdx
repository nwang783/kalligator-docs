This guide starts the control plane, Worker, desktop app, storage services, Agent image, and bundled Package command images.

<Info>
  The current bootstrap script uses macOS command syntax. Run this guide on macOS.
</Info>

## Prerequisites

Before you begin, install:

- Docker Desktop or another active Docker-compatible engine;
- Python 3.12 or later;
- [`uv`](https://docs.astral.sh/uv/);
- Node.js 22.12 or later; and
- npm.

You also need a local checkout of the Kalligator source repository.

## Prepare the repository

Run these commands from the Kalligator source repository:

```bash
cd control-plane
uv sync --extra dev

cd ../worker
uv sync --extra dev

cd ../desktop
npm ci

cd ..
```

## Start Kalligator

<Steps>
  <Step title="Start Docker">
    Confirm that your Docker engine is running.

    ```bash
    docker info
    ```
  </Step>
  <Step title="Run the development system">
    Start Kalligator from the repository root.

    ```bash
    ./scripts/dev.sh
    ```

    The first run builds the Agent image and the Android, Frida, and Traffic Package command images. It also creates a local `.env` file and starts PostgreSQL and Garage.
  </Step>
  <Step title="Wait for the desktop app">
    The script starts the control plane on port `8100`, the Worker on port `8200`, and the Vite renderer on port `5173`. It then opens the Electron desktop app.
  </Step>
  <Step title="Create your first Project">
    Use the desktop app to create a Project. New Projects can start without an APK, scope document, or device.
  </Step>
</Steps>

<Check>
  Kalligator is ready when the desktop app opens and the Worker reports healthy local services.
</Check>

## Local state

The development system writes generated configuration and Worker state under `.env` and `.dev/`. Do not commit these files.

The first development run enables all bundled Packages in `.dev/worker/packages.json`. Later changes in **Settings** are preserved.

## Stop the system

Press `Control-C` in the terminal that runs `./scripts/dev.sh`. The script stops the local API, Worker, Vite, and Electron processes. Docker keeps the PostgreSQL and Garage containers available for the next run.
